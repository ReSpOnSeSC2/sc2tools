# ADR 0035: Local widget previews share pure samples

Status: accepted. Date: 2026-10-25.

The playground renders the existing widget renderer inside the existing overlay preview context. It never mounts a connected overlay client and uses no account token. The canvas is inert and silent; network feed hooks, alert grants, ticker polling and automatic build refresh return before starting work. Direct demos for self-driven widgets use the same boundary.

One JSON fixture supplies API Test samples, browser scenarios, chat, studio, supporter, prediction and ticker examples. Relative clocks and nonces are generated by pure builders. The API runtime image explicitly copies this shared fixture to its expected location; a simulated image-layout test loads the real service there.

Public entry points import a small lazy boundary, preserving the static WebP example in server output. Intersection or an explicit button loads the renderer. A failed chunk retains that image and offers Retry. Settings mounts the preview only while its dialog is open. No new service, endpoint, account integration or infrastructure is introduced.

Tests compare all widget/scenario payloads across API and client builders and mount real widgets through refresh/expiry timers with fetch, socket, direct transport and audio spies. Browser checks use real production CSS at four widths in both themes and synthetic loopback data only. Existing bundle limits remain unchanged.
