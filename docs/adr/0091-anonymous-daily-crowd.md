# 0091. Count SC2 Daily calls anonymously

Status: Accepted

After finishing all five fights in a recorded set, a player can choose to send their five calls to see the crowd split. Practice and shared single fights send no calls. The response reveals only the number of votes and the five distributions, with a floor of 20 votes. Before that floor the response carries no counts. There is no public read endpoint and no account credential on the request.

The API accepts only today's UTC day and its published digest in the public SC2 Daily index. The index comes from one fixed first-party URL with no redirects, a response size cap and deadline. A missing or malformed index cannot admit a vote. The API refreshes publication status after 30 seconds and rereads at the next UTC day. A removed or replaced pack stops accepting calls when the refresh observes the change. Publishers assign each UTC day one immutable recorded pack. The first eligible ballot atomically pins its pack for that day in the tally collection. Every API process checks the shared pin before recording a vote, so a restarted or parallel process cannot count a replacement pack.

An independent bounded in-memory limiter admits eight requests per minute per IPv4 address or IPv6 /64. It normalizes IPv4-mapped addresses and stores only keyed digests. The browser retains a random attempt for its current day, which lets a lost-response retry return the current tally without another vote. When available, the browser's Web Locks API serializes local ballot creation across tabs. The API hashes the day and attempt, stores the digest alone in one of 64 capped buckets, and atomically increments five aggregate counters and the total with the receipt. The collection holds no raw IP, account, browser identifier, or per-person answer row. API request logs keep only the method and route, and Sentry excludes the requests. The pin and buckets expire two UTC midnights after the set begins. After the atomic pin check, each new ballot uses one atomic write and a bounded projection over 64 documents. This preserves the receipt and the tally together across process restarts. Local browser storage keeps the same vote across refreshes when available, and neither the receipt nor the limit establishes a count of unique people.

A recorded fight can be shared as a fragment containing only the scheduled UTC day and a slot. It opens before the call, without modifying a day's streak or submitting a ballot. The existing static asset privacy contract still applies. Only sets completed with the anonymous ballot flow can participate. Live results require the owner to publish reviewed Recorded packs (G6).
