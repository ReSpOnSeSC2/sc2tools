# Temporary overlay samples

Test and real game data are separate inputs. A sample is stored in a bounded, expiring client layer rather than replacing the real `live`, `liveGame` or `session` state. Real widget instances stay mounted underneath the covered slot, so randomizer ledgers, Ghost practice state, session clocks and live updates survive Stop. Natural real visibility deadlines keep running while covered; stopping a sample does not reopen an already-expired real announcement.

Every sample expires after `TEST_DURATION_MS`. Explicit test nonces are deduplicated in a bounded page-local ledger, including after expiry. The paired session event carries the same nonce so an old replay cannot revive a completed sample. `overlay:clear` has `{scope:'test', widget}`. Legacy missing scopes also mean test-only; unknown explicit scopes are ignored. A targeted Stop reveals only that widget's real state.

Before broadcasting a test, the owner-authorized route reads the existing `LiveGameBroker.latest(userId)`. Loading, started and in-progress phases return `409 live_match` unless `force:true` is a literal boolean. Settings requires an explicit Send anyway action, or offers a local `?demo=1` page. Ownership and ordinary rate limits still apply to forced requests. The guard reflects the latest agent report; it cannot detect a game that an offline agent has not reported, so tests are always sample-only even when no warning is available.

The local page reuses the API's pure sample builder on the server and renders the actual widgets. It creates no overlay socket. An explicit preview context disables Studio/engagement HTTP, chat transports, configuration polling and engagement reporting in sample trees. The same boundary prevents a temporary sample tree from opening duplicate live feeds beside the retained real widgets. Local previews are labelled sample data and can replay their 20-second window. They are never sent to another Browser Source and do not update real stream state.

No production test broadcasts were used for development. Tests use local Mongo/HTTP, injected socket events and fixture-only browser renders. No new infrastructure or AI features/calls are introduced. Deploy server and clients together so older clients do not retain their previous destructive interpretation of Stop; refresh long-running Browser Sources after deployment.
