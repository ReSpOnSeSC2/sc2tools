# SB2: game chapters for the stream video

**Shipped (PR stacked on #995, SB1).** End stream can write one chapter per game into the description of each YouTube archive SC2 Tools created ("0:42:10 Game 4 · PvZ win vs 5.1k", rating rounded to 100, no names). The Stream Dock shows and copies the same list as text for Twitch and Kick. An optional agent switch adds an OBS recording marker at each game start. Agent 0.26.0 (unchanged), ADR 0105.

- **Gates, all off by default.** Server `YOUTUBE_CHAPTERS_ENABLED=true` (exact value), the streamer's Dock switch (`youtubeChapters`), and existing streaming consent. Each archive offered the chapters leaves a row in `youtube_chapter_receipts` (video, state, reason; no text; 90-day TTL; purged with the account).
- **Block.** Between `-- SC2Tools game chapters --` and `-- end of SC2Tools game chapters --`; a rerun replaces it, other text is untouched. YouTube rules (0:00 first, three or more, ten seconds apart, 5,000 bytes) refuse the write and the Dock says why. The Twitch/Kick copy has none of those rules.
- **Review fixes.** A chapter only covers games that started while its own video ran (the broadcast's end is passed to the composer). Game starts use `gameStartMs` (startedAt first). The OBS marker treats a corrected loading identity (same episode) as the same game. Added the server gate and receipts the spec asks for; removed the two `any` casts.
- **Tests.** API: streamChapters, youtubeStreaming, gameDesk, youtubeCreateOperationLedger (incl. the real `recentOwnedBroadcastIds` sort), plus 7 neighbouring suites (accounts, GDPR, schema) all pass; API tsc clean. Agent: 5 stream-title files, 168 passed. Web: tsc, eslint, ui-lint clean; components/dock 183 passed.
- **Mutations.** 9 API (video end ignored, copy under YouTube rules, gate ignored, receipts dropped, minimum dropped, startedAt ignored, ledger order, Dock mark beating the open stream, end not passed) all killed; 1 agent (episode match) killed.
