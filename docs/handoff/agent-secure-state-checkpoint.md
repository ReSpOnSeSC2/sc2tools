## Core contract

`agent_credentials.py` imports the existing `_STATE_SAVE_LOCK` and adds no competing writer lock. Storage and crypto are narrow injected protocols; importing the module performs no filesystem or native crypto work. C2 adds central state readers/writers and explicit migration admission. Runner, pairing, recovery, OBS, GUI and support activation are coordinated separately; this central change is not a standalone rollout. OAuth credential-store behavior remains unchanged.

- `load_credentials(storage, crypto)` reads the full pointer document and only its exact selected generations. It reports missing pointer, explicit cleared slot, available slot and unreadable slot separately. A corrupt/unsupported/legacy-only document cannot become a writable default. A selected missing/corrupt/undecryptable generation retains its opaque reference; legacy plaintext and orphan files are never recovery sources. Reads never create directories, migrate or write.
- `prepare_transaction(snapshot, projection_bytes, *, crypto, device, obs, generation_id)` prepares immutable ciphertext and a complete JSON document. The caller supplies the full nonsecret projection without `credentials`, `device_token` or `obs_password`. Each of the two slots has versioned selection metadata, independent revision and generated basename. KEEP preserves the exact reference without decrypting it; SET allocates a new immutable generation and revision; CLEAR selects null with a new revision without decrypting or allocating. The encrypted envelope binds schema, slot, generation, revision and exact nullable device owner metadata from the same full document. Unknown metadata is never invented; changing unknown to known metadata cannot rebind an old device generation. OBS is installation local and has no cloud-owner binding.
- `commit_transaction(storage, crypto, prepared)` validates the prepared transition under the existing reentrant writer serialization. The physical store identity and exact prior raw document fence publication. New generation bytes are exclusively written/flushed, read back and decrypted/validated before the full document is replaced last. A retry reuses the same generated names/ciphertext. Existing generations are never overwritten or deleted. The prepared object retains bytes and opaque identity, without storage/crypto callbacks, handles or credential tickets.
- A replacement failure is followed by an exact reread. The intended document proves committed selection; the prior document proves failure; another/unreadable document is indeterminate. Indeterminate outcomes never trigger an automatic rollback over a potentially committed choice. A later exact retry can establish the intended commit. The core never activates API/OBS/shared state, so post-commit activation failures remain a later integration responsibility.

Protocol methods are `identity() -> bytes`, `read_pointer() -> bytes | None`, `read_generation(name) -> bytes`, `create_generation(name, data) -> None`, `replace_pointer(expected_raw, full_document) -> None`, and `capacity() -> (count, total_bytes)`. Generation creation must be exclusive and return only after complete write/flush; pointer replacement must check the exact expected raw document. The crypto protocol is `protect(bytes) -> bytes` and `unprotect(bytes) -> bytes`. The coordinator owns the separate Windows/CurrentUser adapter and its tests.

Credential values, full raw documents and ciphertext are private internal values with hidden representations. They are not support/export/UI DTOs. Fixed storage errors contain closed codes. Inputs reject subclasses/coercions at primitive boundaries. Internal limits are 16 KiB UTF8 per secret, 64 KiB per encrypted generation, 128 owned generations and 8 MiB owned generation bytes. The byte budget is an additional defensive bound; with the count and per-file limits it is not claimed as an independently discriminating production mutation. There is no new credential-sized limit on the existing uploaded/path state document. Directory inventory, root creation and handle safety belong to the finite storage adapter; inventory is never used to select or decrypt an orphan.

## Central state and explicit migration

- `load_state(..., storage=None, crypto=None)` stays strictly read-only. Its private provenance distinguishes first-run missing, legacy, selected and unreadable documents. Selected null/missing/undecryptable slots remain distinct and never fall back to coexisting plaintext or orphan files. Pre-instance legacy/nonsecret reads do not construct the native store. Unknown nonsecret fields remain available in the private raw document for preservation. Corrupt/unsupported documents remain blocked from blind overwrite.
- `_snapshot` excludes both runtime secrets before dataclass serialization. Runtime secrets also have hidden `AgentState` representations. Private contexts, status, pending intentions, crypto/storage callbacks and owner tickets are dynamic attributes outside the serialized dataclass. Every secure write composes the full nonsecret state plus the selected references, preserving unknown nonsecret fields and the existing uploaded/container snapshot protections.
- `save_state` is opaque KEEP for an existing selected target. It rejects uncommitted shared token/password/owner edits. A fresh unmanaged `AgentState` can initialize only an actually absent target, treating its provided initial fields as explicit first SET/CLEAR; no existing legacy/invalid/unsupported target is implicitly migrated. Unsupported DPAPI/platform storage fails with a fixed error and has no plaintext/keyring fallback.
- `commit_state_credentials` requires the expected revision for each changed slot. Device changes additionally require the captured current non-null owner epoch; device SET supplies an exact nullable `device_owner=(user_id, paired_at)` candidate without first assigning shared fields. OBS-only changes do not depend on cloud epoch. After known commit, the same shared `AgentState` receives the committed credentials/metadata and private selection. Failure keeps the old shared values; an indeterminate outcome blocks ordinary writes until explicit recovery. The helper invokes no queue/network/OBS/Qt callbacks.
- Pure private `credential_revision`, `credential_status` and `credential_scope` provide admission metadata without reference names or values. `mark_device_retired(durable=False)` removes the runtime device token and its private loaded value, retaining the old opaque reference and visible retired status after failed revoked CLEAR. A later ordinary KEEP cannot revive that runtime token. Restart is not promised cleared while old durable selection remains; only known committed CLEAR supports durable status. Runtime epoch/cache/client retirement remains the coordinator's responsibility.
- `migrate_legacy_state(state_dir, instance_lock, ...)` requires the actual acquired matching `AgentInstanceLock` before storage setup and around its IO. `prepare_legacy_transaction` is an explicit admission path, never a loader fallback. Both legacy secrets are encrypted/staged before one complete pointer-last publication; original bytes survive precommit failure. Exact nonsecret legacy data is preserved. An already selected document allocates nothing; stale plaintext keys can be removed while preserving even unreadable selected references. Missing first-run state commits explicit cleared slots. No environment credential is read or migrated.
- One private pending prepared operation per state/instance guard reuses staged encrypted generations for same-intent retries. It carries no publication authority; current epoch/revision/raw-document/store admission is checked again. These private pending values never enter snapshots or support output. There is no eager orphan cleanup or newest-file guessing.
