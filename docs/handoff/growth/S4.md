# S4 · Answer as me

- **Shipped.** Open live replies in Chat command settings and choose **Answer as me** on a live Twitch, Kick or YouTube command. The reply uses the saved command and the owner's existing chat-send grant.
- **Authority.** A Clerk session and an owned token are required. Each click targets the verified source and uses a native reply ID where supported. The OBS and preview paths keep their existing behavior.
- **Delivery.** The existing cooldown and a bounded receipt cover duplicate clicks and uncertain delivery. The route omits private command details. Twitch checks Shared Chat before composition and again before sending, then checks the grant.
- **Checks.** 213 API tests across nine suites and 153 web tests across 14 files passed. Both TypeScript checks, scoped lint and complexity, all 25 UI rules, UI lint, help indexing and diff checks passed. Changed-file lint diagnostics match exact S3.
- **Mutations.** All ten exact-match mutations failed their intended assertions and restored matching source hashes.
- **Build.** The production build passed. On Windows, Dock measured 224,318 of 225,000 gzip bytes (−1,185 versus S3). Composite overlay was the only overage at 241,207 (+41 versus S3, which had the same Windows overage).
- **Fixture.** Inspected six offline Chromium captures at 360, 768 and 1280 px in both themes. Checked opening, retry, focus, keyboard and 44 px targets. Each case made two mocked Twitch checks and one mocked send with zero external HTTP requests.
- **Not verified.** Real provider accounts and delivery. Twitch can start Shared Chat in the interval after the final check because it offers no atomic check-and-send for this grant.
