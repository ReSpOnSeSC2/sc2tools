# N5 · Private Discord embeds

- **Shipped.** Automatic posts use fixed text, race labels and bounded figures. Opponent identities and ratings stay private. Own MMR and inbox milestones require separate opt-ins. A manually approved battle report can keep its active public share link.
- **Delivery.** Retire legacy payloads without discarding dedupe receipts. Retry a pending milestone enqueue from the stored bell without replaying socket or push. Check current consent at dispatch.
- **Settings.** Require a browser session for changes. Reconnecting the same webhook returns the original channel without altering its settings. Unique indexes fence simultaneous connects and preserve the three-channel cap.
- **Verification.** 128 focused API tests across eight cached MongoDB suites, 59 web tests across six files, both TypeScript checks, scoped lint and complexity, help index, 25 UI rules, UI lint and diff checks. Ten exact mutations failed on intended assertions, and hashes matched after restoration.
- **Browser.** Inspected the signed-out fixture with synthetic owner data in light and dark at 360, 768 and 1280 px. The production build and exact budget comparison are recorded on the PR.
- **Limits.** No live webhook or production account tested. A request already handed to Discord cannot be recalled. Remove an old connection before adding a replacement credential for its webhook.
