# S5 · Delayed stream viewer

- **Shipped.** Streamers can enable a signed-out viewer page in Settings → Profile, choose one Stream Dock Browser Source, and set a 5–60 minute delay. Start a new session in the selected Dock to publish completed 1v1 results.
- **Publication.** The page shows win/loss, opponent race, and known ladder map. It excludes live games and records without a valid replay start. Series, rating, predictions and builds wait for an equally safe delayed cohort.
- **Consent.** The opt-in binds to the existing public consent epoch. Source rotation or revocation closes the link. Every rate-limited API request checks current consent and reads a bounded set of currently visible games without a result cache.
- **Browser.** The initial HTML contains no result rows. The browser checks publication before display, revalidates on return and polls every minute while visible. The public route is no-store, noindex and excluded from analytics. Telemetry uses route templates.
- **Checks.** 113 API tests across seven suites and 152 web tests across ten files passed. Both TypeScript checks, scoped lint and complexity, 25 UI rules, UI lint, help indexing and diff checks passed. Changed-file lint diagnostics match S4.
- **Mutations.** All ten exact-match mutations failed their intended assertions and restored matching source hashes.
- **Build.** Next production build passed. The viewer uses 125,155 of 200,000 gzip bytes. Windows Dock measured 224,339 B (+21 versus S4). Composite overlay was the only Windows overage at 241,227 B (+20 versus S4, which had the same local overage).
- **Fixture.** 18 signed-out or synthetic-owner Chromium cases at 360, 768 and 1280 px, including same-document Back after revocation. Inspected public and Settings in both themes. Twelve axe reports had no serious or critical violations.
