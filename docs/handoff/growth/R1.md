# R1: game-start scouting lists each player's last five games

**Shipped.** API, desktop agent 0.25.0 (set on `main`, not published) and help. The Companion's floating Scouting report lists the builds from each player's last five games, newest first, each with your result, the map and the age; a row opens that game's build order. "You" is your games in this matchup. "Opponent" is your games against this player in every matchup, linked accounts included. The loading-screen strip shows both lists in short form. A first meeting says so; an opponent whose account is not confirmed yet reads "Not identified yet". A setting that starts on keeps a pinned report closed while there is no earlier game of the opponent to show.

- **Where the report's two build orders come from (traced).** The agent's `live/*` bridge posts the live envelope; `OverlayLiveService.buildFromOpponentName` adds `streamerHistory`; `LiveGameBroker.latest` holds it; the Companion polls `GET /v1/me/live/snapshot`; `companion_page._live_context` feeds `CompanionPanel("scouting")`, and a chosen game's steps come from `GET /v1/games/<id>/build-order`. The strip reads the device brief (`agentScouting.buildScoutingBrief`, `scouting:brief`).
- **Decisions (ADR 0077).** Both lists ride in a new `streamerHistory.recentBuilds`; an older agent ignores it and the new agent draws today's report when it is missing. The opponent's list is matched by toon handle or character id only and is null while neither is known, so a name-only match is never called a first meeting; a failed read leaves the field out. A Random pick narrows nothing (stored games keep the spawned race). The broker removes the lists from both overlay emits, so OBS receives nothing new; the spoken report is unchanged. The brief carries result and build only and drops the lists first at its byte cap; the strip cuts names at 22 characters over four lines so all five games fit. A poll that lands before the server's enrichment keeps the game's last enrichment (same account, game and opponent), as the web overlay does. The chosen row keeps a dark fill (every text colour at least 4.5:1) and is marked in cyan.
- **Setting.** `scoutingSkipFirstMeeting`, on by default, gates only the pinned report's own opening; in team games the selected enemy's history decides. It is the one Companion preference that starts on, so the "nothing appears by default" test names it.
