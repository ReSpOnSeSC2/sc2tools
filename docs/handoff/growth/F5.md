# F5 · SignPath prerequisites

- **Blocked on G5.** The repository has no approved open-source license. The owner must also designate the signing roles and obtain SignPath Foundation approval. Installer privacy controls overlap with the owner's in-progress packaging changes.
- **Verified.** Main contains the opt-in signing workflow and setup notes in [the packaging README](../../../apps/agent/packaging/README.md). The release workflow keeps signing disabled until the owner configures it. Main has no root license and the current NSIS installer has no privacy-policy step.
- **Public policy after approval.** Link “Code signing policy” from the home and download/release pages. Name the approved provider, certificate holder and designated authors, reviewers and approvers. Link [the privacy policy](https://sc2tools.com/legal/privacy). Describe signature and SHA-256 verification for the GitHub release installer.
- **Installer work after the packaging changes land.** Surface the privacy policy during setup and make data transfer choices effective before the Agent first runs. Exercise clean and upgrade paths, including silent install and existing opt-outs.
- **Owner.** Choose the license, confirm bundled components qualify, assign roles with MFA, apply, and configure the approved signing policy. Verify the first signed build before publishing it as signed.
- **Reference.** [SignPath Foundation conditions](https://signpath.org/terms.html).
