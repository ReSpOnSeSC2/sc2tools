# M2 · Replay-reported match scores

- **Built.** Each player can select a local replay from their seat link and report the result. A matching report from the other seat confirms it, including after the series ends. The host or both seats can undo the last score. Manual scoring remains available.
- **Privacy.** The worker starts only after file selection. The dialog shows win and loss options. The request carries the canonical map key, timing, winning seat and room-specific digests. Replay bytes and raw identities stay in the browser. Match Room requests are excluded from API error and trace reporting.
- **Consistency.** Reports follow the fixed veto order and use the displayed room revision. Failed writes leave the parsed result available for retry. Older API writes invalidate stale replay evidence while preserving the current manual score.
- **Checks.** 150 focused API tests in nine suites with Mongo and 427 focused web tests in 37 files passed. TypeScript, changed-file lint and complexity, and all 25 UI rule tests passed. Eight preflight-validated mutations failed their intended assertions with the original bytes restored.
- **Build and browser.** `/match/room` is static at 170.4 kB against 215 kB. The Windows overlay overage matches the D3 base at 241.2 kB against 240 kB. All 21 Chromium cases passed at 360, 768 and 1280 px with both themes and 18 clean axe reports. The shipped WASM worker read the checked-in replay at all three widths.
- **Not verified.** End time, duration and map agreement between two separately recorded copies of a real match. The header protocol omits observers and cannot establish the recorder's identity. The existing presets assign the full map order before play.
- **ADR.** [0093](../../adr/0093-replay-reported-match-scores.md) records the replay evidence and rollback rules.
