# N3 · Private browser notification choices

- **Shipped.** Settings → Preferences offers independent, default-off choices for ladder milestones and other bell notifications. Explicit legacy choices stay within their earlier scope.
- **Device control.** An active worker must answer the protocol probe before enable. Older clients can refresh their own enrollment. New enrollment and account transfer require the explicit enable protocol. The ten-device cap survives endpoint rotation.
- **Privacy.** The API and worker use fixed copy and opaque grouped tags. Old queued payloads cannot expose bell text or private destinations. Current-device off removes the owner's registration and unsubscribes locally. Account export includes only device metadata.
- **Proof.** API Jest 157/157 across 10 suites and web Vitest 104/104 across nine files. Both TypeScript checks, scoped ESLint and complexity, worker syntax, 25 UI rules, UI lint, help index and diff checks passed. Ten exact mutations hit their intended assertions; restored hashes matched.
- **Build and browser.** Next production build passed. Windows Settings was 207,026/260,000 B gzip, Dock 224,332 B (−7), and composite overlay 241,224 B (−3 versus exact S5, the sole inherited Windows overage). Six isolated Chromium cases covered updates, permissions, retry, owner switch and unsubscribe with no outbound requests. Inspected twelve captures.
- **Not verified.** Native iOS permission, live push transport and delivery with the deployed VAPID setup. Previously displayed alerts may remain in OS history. Browser expiry without a replacement requires an enable click.
