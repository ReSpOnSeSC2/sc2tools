## Implemented contract

- `support_diagnostics.py`: frozen, versioned support information and nine fixed diagnostic rows. Explicit primitive projection rejects container/string subclasses, non-string dictionary keys before lookups, arbitrary objects, unknown fields/metrics, arbitrary filter labels and raw exception detail. Missing numeric/probe facts remain unavailable. Agent versions are numeric three-component versions; OS names, update channels, pool modes, regions and error kinds are closed sets. OS versions, dates and API hostnames have bounded format validation. API URLs retain only their validated hostname. Counts reject booleans, negatives, non-finite and oversized values.
- User identity is SHA256 of the bounded UTF-8 user ID, first eight lowercase hex characters. Unbound `project_support` never emits a device suffix. The guarded collector may emit the last six characters of a canonical lowercase 24-hex device ID returned by the separate current-binding validation callback. Raw IDs, tokens and validation closures never enter results.
- `support_redaction.py`: bounded byte snapshots are joined before strict UTF-8 decoding and redaction, including token/Unicode splits across chunks. Explicit sensitive bindings are replaced; only a fixed event/key/value grammar with closed events/errors and bounded numbers survives. Credential, JWT, BattleTag, toon, email, Windows/UNC/POSIX path, replay filename, URL, arbitrary name and other uncertain free-text records become fixed omitted markers. This uses cheap grammar rejection rather than unanchored sensitive-pattern regexes over unknown text. Structured records project known safe fields without recursion. Incomplete/oversized physical lines are omitted whole; no sensitive value or raw line is truncated into a retained fragment. Invalid/oversized bindings reject the whole document, including control/newline-bearing bindings.
- `support_export.py`: a plan holds generated aliases, defensively copied immutable redacted UTF-8 bytes, exact lengths/hashes and a canonical hashed manifest. The only aliases are `diagnostics.txt`, `state-summary.json`, three numbered parent log slots and eight numbered worker log slots. The state summary derives from the projected support fields; raw state/file objects cannot be selected. Canonical document/log validation also rejects direct construction from arbitrary bytes or inconsistent omission metadata. Visible omitted markers cannot exceed the omission count; additional cap-dropped lines require truncation, and success/failure codes must match their fixed metadata contracts. Generated non-log documents require zero omissions, no truncation and `ok`. Preview and the later writer consume the exact entries in the plan. Omission counts, truncation flags and validated fixed redaction result codes appear in the manifest and survive reviewed-entry reconstruction. There are no source paths, mutable buffers, lazy readers, tickets or callbacks in result/plan fields.

The implementation caps are policy defaults for this slice: 64 KiB per diagnostic/state document, last ten errors, three parent/eight worker logs, thirteen entries, 512 KiB raw/output per log, 8 MiB total plan, 32 KiB physical lines, 1,024 input chunks, 64 sensitive bindings of at most 4,096 characters/64 KiB aggregate UTF-8, bounded primitive dictionaries of at most 64 short exact-string keys, and at most 32 named metrics (the current explicit lists contain 25). Overflow/omission is represented by fixed safe metadata.

## Runtime integration obligations

`collect_diagnostics` and `collect_export_plan` require `is_current` and `is_cancelled`. Guard exceptions and non-boolean results retire output. Guards run before work, after each external callback, and before final publication/finalization. Runtime adapters must capture a monotonic owner/connection/binding/run generation: owner A -> B -> A must not make the first A current again. The device callback must validate the captured authenticated API, owner, token, epoch and state namespace. The pure layer cannot establish runtime authentication or locking itself.

No credential-bearing callback/ticket is retained in a snapshot or plan. The later filesystem writer must independently recheck the external plan owner/run guard before saving, perform the reviewed containment/link/rotation/exclusive-creation checks, and write exactly the frozen bytes. These are obligations for later slices, not validation claims here.
