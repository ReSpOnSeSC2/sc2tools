## Behavior and bounded data

- Current ladder pool, source, fetched date and age reuse the public `/v1/seasons` client cache. Edition-name matching shares the existing Daily Pulse key behavior through a small pure module, preserving Roman numerals. Persisted/Liquipedia data needs a measured fetch within eight days. A minute-local clock expires a long-open pool without changing its personal sample window or adding requests. Stale/fallback/unknown pool data shows historical stats but suppresses suggestions/copying.
- Ranking matchup defaults to most played, or All for a Random race filter. The planner compares all opponent races while retaining other active filters. Filter-range, 90-day and measured current-season windows plus veto count 1–3 are supported.
- Existing `/v1/maps/matchups` and `/v1/maps` supply personal cells and recent form; SWR reuses identical existing queries. There is no per-map request fanout or new server aggregation. One cacheable public guide-index response supplies every published community map cell, with its snapshot date and worker era shown. Community comparisons require an explicit own race and exact published matchup side; unavailable/mixed-race cells are not invented.
- Win rates and Wilson 95% intervals use decided games. The lowest lower bounds receive Suggested veto, with a hard five-decided-game floor independent of the historical Min games picker. Ties/other results remain visible in sample notes. Copy has a selectable-text fallback. A failed or stale personal sample pauses recommendations.
- Pool-map and matchup cells open one on-demand, latest-100 games page using the selected cohort. Combined edition records carry the full observed-name cohort through `map_exact`: at most 16 exact names and 2048 encoded bytes, validated once more before Mongo `$in`. Malformed/oversized cohorts return 400 instead of broadening. This reuses the existing list/analytics/neighbor reads with no new aggregate. Distinct prefixes and Roman numerals cannot leak into a drilldown. The footer applies this cohort to global filters; its visible Map chip clears all exact-name fields, editing the map discards the old cohort, and these session-only fields never persist. Game navigation retains the same exact cohort.
- The historical list combines the same edition aliases, supports current-pool-only (fresh pool defaults on, stale defaults off), persistent sorting, map/matchup drilldowns and separate Preview map controls. `?focus=` matches edition aliases, lowers the display floor, highlights/scrolls to the map and opens its games. Recent form follows the API's chronology, oldest to newest; when multiple alias samples lack timestamps it reports unavailable rather than inventing order.
- Map guides render a lazy private “You on this map” panel only after signed-in auth resolves. The private sample explicitly uses ranked 1v1/current-worker-era games, and its caption explains the sample-window difference from community data. Own-race selection aligns personal and community sides; failures offer Retry and signed-out views request no private map data.
