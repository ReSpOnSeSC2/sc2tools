# Agent feature and implementation audit — 2026-10-24

Baseline: Agent 0.23.1 (`fa20d0f4`). This report describes the subsequent audit
patch, not a claim that the baseline already contained these fixes.
Release target: Agent 0.24.0. Publication and local installation were authorized
after this audit; final artifact and deployment evidence belong in its release notes.

## Scope

The review covers Companion navigation and layouts; native Opponent, Scouting,
Session and Ghost panels; race artwork and click-through behavior; speech;
replay-based build ranges/icons; local, cloud and admin Ghost sources/references;
pre/post-game check-ins; widget-only Randomizer configuration; Hybrid Teams;
pairing and account recovery; replay upload/history/archive durability;
Streams/OBS account boundaries; updater safety; and general Agent recovery UI.

The implementation uses synthetic accounts/transports and isolated replay/Qt
fixtures. It does not read production credentials, upload real replays, alter
OBS, create broadcasts, or change the installed Agent as part of the audit tests.

## Confirmed issues and corrections

| Area | Reproduced defect | Correction |
| --- | --- | --- |
| Companion snapshot | A captured owner could label a response fetched with a replacement token/API. | Bind the request to the exact captured connection. |
| Ghost | Private cloud replay rows, references, cached targets and late writes survived account changes. | Owner-scoped caches, queued-write admission and request generations; retain only explicitly local targets across accounts. |
| Replay ingestion | Late acceptance could advance another account's cursor, post MMR or feed check-in callbacks. | Captured API/owner generations and atomic acceptance admission, including terminal rejection and queued callback paths. |
| Replay archives | A durable task did not record its cloud owner. | Owner-bound journal records; retain foreign tasks; verify legacy tasks with the existing owned-game endpoint before reassociation. |
| Build check-in recovery | Discarded requests left loading/write slots busy after relinking; queued input could use a replacement API. | Reset request epochs and loading slots on connection transitions, pin queued input to its captured API, retry same-owner drafts and clear foreign-owner work. Completed cards stay terminal. |
| Streams and OBS | In-flight catalogs, secrets and saved broadcast setup could survive pairing changes. | Whole-operation connection guards, immediate secret masking and owner-verified setup recovery; preserve existing broadcasts and local OAuth mode. |
| Scouting pin | The fixed-height timeline extended below the panel and decorative bezel. | Scroll-backed content with safe frame margins and reachable controls. |
| Randomizer background work | Hidden settings repeatedly fetched account pool/options/intent. | Lazy visible-page reads; explicit pending writes still finish and check-in remains independent. |
| Randomizer retry | A failed save disabled retry and assistance-off text hid its error. | Preserve the dirty draft, restore retry and prioritize actionable errors. |
| Update transport | Extra hosts permitted insecure schemes; redirects bypassed the allowlist. | HTTPS policy, explicit loopback development exception and pre-follow redirect validation. |
| Update transfer | Partial HTTP failures left staging files; oversized/malformed downloads were not bounded early. | Strict metadata validation, a 1 GiB installer ceiling, streaming size checks and failure cleanup. |
| Recovery UI | Narrow update, import/archive and status actions clipped or forced horizontal overflow. | Natural action wrapping, full-width recovery rows and responsive Settings forms. |

## Usability improvement

Native panel positions now persist locally. Placement is validated and clamped
to available screens, including negative-coordinate and removed monitors. Saves
are debounced and only admit real user/native moves; preview, initialization and
account-clear transitions do not overwrite saved placement. Already-admitted
moves survive immediate hide, minimize, close and quit. The reset action does
not enable panels or change their sizes.

## Preserved behavior

- Compact, Standard, Detailed and Full workspace dimensions and manual sizing.
- Independent feature switches, mode gates, click-through and no focus stealing.
- Historical scouting only; no invented live enemy technology or team ratings.
- Started/completed replay timing meanings, selected replay perspectives and drafts.
- Widget-only Randomizer draws, animation and audio; optional native scouting voice.
- Explicit team confirmation and per-game manual team Ghost.
- Pairing, local replay history, local Ghost targets and durable retry semantics.

## Verification

Focused regressions include failing-before/passing-after account switches,
barrier-controlled races, local HTTP redirects/interrupted transfers, real Qt
6.11.2 with production styling/Segoe fonts, all race skins, high-DPI scaling,
negative/missing monitors and recovery controls at minimum widths.

A separate visual sweep captured Dashboard, Recent games, Activity log, Settings
and Streams at 480 and 520 pixels in all four themes: 40 captures, with no
horizontal overflow or buttons narrower than their minimum hints after fixes.

The complete suite runs from `apps/agent` using the build environment:

```powershell
.build-venv/Scripts/python.exe -u -m pytest -ra --durations=20 -o faulthandler_timeout=120 -p no:cacheprovider --basetemp C:/SC2TOOLS/.tmp/pytest-agent-deep-final
```

Final consolidated verification: all 3,234 runnable cases verified across the
complete run and focused follow-ups, with one intentional non-Windows-path skip
on Windows.

- Complete run: **3,231 passed, 3 failed, 1 skipped**, 945.49 seconds. The three
  failures exposed older test-fixture assumptions: an already-accepted archive
  task lacked its owner, and two team Ghost tests examined slots before the new
  owner's asynchronous refresh completed.
- Corrected those fixtures without changing runtime code or removing assertions.
  The archive fixture now carries its owner; team fixtures await the current
  owner's refresh and explicitly assert the saved PvT slot before team actions.
- Follow-up archive/gate/ownership/journal families: **43 passed**, 15.57 seconds.
- Follow-up Ghost/Teams families across ten files: **126 passed**, 37.15 seconds.
- No runtime code changed after the complete run. All three failing cases passed
  in those follow-ups; the other 3,231 cases retain their complete-run result.
- `git diff --check` passes. Independent implementation and documentation reviews
  found no remaining concrete blocker in the reviewed changes.

Complete-run output is saved locally at
`C:/SC2TOOLS/.tmp/agent-deep-full.log`. This is combined verification, not a claim
that a second complete run was performed after the fixture corrections.

installed 0.23.1 update. Its 667 ERROR records comprise 619 OBS connection
failures, 32 missing-ability diagnostics and 16 associated parser context lines.

already prevents that SDK error flood.

Missing-ability diagnostics do not abort parsing. Build timelines use tracker
events, and macro extraction has build-aware numeric mappings. An unknown
general spell can still be omitted from cast visualization and recorded as

reproduction; this historical tail does not establish a current Agent failure.

## Remaining external limits

- Publisher signing is not configured. HTTPS, size and SHA-256 checks do not
  establish an Authenticode publisher identity. No signing safeguard is disabled.
- SC2's local API does not provide verified active-server detection; Session
  continues to label the rating region honestly.
- No new manual human ladder/team match or live YouTube/Twitch/Kick/OBS session
  was performed by these tests. Mocked/offscreen checks are not that verification.
